The 15 Lexical & Structural Features Encyclopedia

Complete definition and cybersecurity defense rationale for every extracted feature
Feature Name Data Type Cybersecurity Rationale & Threat Behavior Benign Baseline
url_length Integer Phishers often construct lengthy URLs to disguise target destinations, embed tracking tokens, or pass security filters. Typically < 75 characters
domain_length Integer Long domains frequently indicate typosquatting, hyphen stuffing, or compounding brand names (e.g. paypal-security-update-center.com). Typically < 20 characters
num_dots Integer Excessive dots indicate nested deceptive subdomains designed to deceive mobile users where only part of the URL is visible. Typically 1 or 2 dots
num_hyphens Integer Rare in legitimate major brand domains, but ubiquitous in phishing URLs to mimic registered brands without purchasing the authentic domain. 0 or 1 hyphen
num_at_symbols Integer The @ symbol triggers browser credential parsing: browsers ignore everything before the @ and navigate to the host after it. Strictly 0 in benign web URLs
num_question_marks Integer Delimits query parameters. Multiple question marks often appear in obfuscated redirection chains and dynamic relay scripts. 0 or 1 question mark
num_equal_signs Integer Reflects key-value URL parameter depth. Heavy counts indicate automated token dispatching and session exfiltration queries. 0 to 2 equal signs
num_underscores Integer Often utilized in fake script paths (e.g. cmd=_login-run, _session_id) and hidden directory trees. 0 or 1 underscore
num_digits Integer Benign domains rarely contain sequences of numbers. Attackers use digits for automated domain generation algorithms (DGAs) and ephemeral hosts. Low count (0 to 3)
num_subdomains Integer Calculated by stripping root domain and TLDs. Attackers nest subdomains like bank.security.login.attacker.com to trick victims. 0 (root) or 1 (e.g. www)
has_ip_address Binary (0/1) Direct IP usage (e.g. http://192.168.1.10/login) completely bypasses DNS domain registration to avoid domain takedown lists. Strictly 0 (always domain names)
has_https Binary (0/1) Indicates whether the URL begins with HTTPS. While modern phishers also use free TLS certificates, unencrypted HTTP URLs carry elevated risk. 1 (HTTPS standard on modern web)
path_length Integer Deep directory structures (e.g. /cgi-bin/webscr/login/auth/verify/index.php) simulate legitimate enterprise authentication flows. Short or standard path (< 35 chars)
has_suspicious_word Binary (0/1) Flags urgency and credential lures such as login, verify, wallet, suspended, banking. 0 in general content URLs
num_slashes Integer Measures URL path depth. Abnormally high slash counts reflect deeply nested redirection folders designed to evade basic crawlers. Typically 2 or 3 slashes

Viva Voce Defense Guide (Questions & Defensible Answers)

Prepared specifically for academic evaluation, viva examiners, and seminar presentations

Q1: How does the system classify a URL without looking at the webpage content?

PhishGuard uses purely lexical and structural URL analysis. Attackers engineer URLs with structural anomalies to deceive humans (such as adding multiple subdomains, inserting hyphens into brand names, or using raw IP addresses to bypass DNS takedowns). By extracting 15 statistical features directly from the URL string, our Machine Learning models identify non-linear mathematical patterns unique to phishing URLs in sub-millisecond execution time, completely offline.

Q2: Why not just fetch the webpage content, screenshot it, or query WHOIS APIs?

Fetching remote web pages introduces three critical vulnerabilities:
1. Security & Exploitation: Visiting an active malware site exposes the scanning server to drive-by downloads and browser exploits.
2. Cloaking & Evasion: Phishing kits actively detect automated scanners (via IP ranges, User-Agents, or CAPTCHAs) and return fake benign pages when inspected.
3. Latency & Cost: HTTP requests, headless browser rendering, and WHOIS API queries take 2–10 seconds per URL and often incur rate-limits or API fees. PhishGuard evaluates in under 1 millisecond at zero API cost.

Q3: Why did Random Forest outperform Logistic Regression?

Logistic Regression is a linear classifier that assumes each feature contributes independently to the log-odds of a URL being phishing. However, URL risk factors exhibit heavy non-linear feature interactions. For example: having 3 hyphens in a URL path is completely benign for an article title (e.g. nytimes.com/top-ai-trends-in-2026), but having 3 hyphens combined with a suspicious word (paypal-verify-login-update.com) is an extreme indicator of phishing. Random Forest, an ensemble of 100 de-correlated decision trees, easily models these multi-condition threshold splits without requiring manual polynomial feature engineering.

Q4: What are the main limitations of purely lexical detection?

1. URL Shorteners: Services like bit.ly or t.co produce short, benign-looking URLs that mask the real destination without network expansion.
2. Compromised Legitimate Websites: If an attacker uploads a phishing form onto a hacked authentic domain (e.g. university.edu/~student/login.html), the domain features will look benign.
3. Zero-Day Evasion: Attackers who intentionally craft minimalist URLs that mimic legitimate domain structures without classic lure keywords.

Q5: What is the future scope to enhance PhishGuard?

1. DNS & TLS Certificate Heuristics: Passive DNS inspection (TTL values, ASN risk score) and Let's Encrypt certificate issuance age without downloading page payloads.
2. Deep Learning: Character-level Convolutional Neural Networks (Char-CNN) or Transformer embeddings (BERT/RoBERTa) to automatically learn sub-word lexical nuances and homoglyph attacks (e.g. Cyrillic 'a' replacing Latin 'a').
3. Client-side Browser Extension: Packing the lightweight Random Forest inference into ONNX Runtime Web for real-time edge protection directly inside Google Chrome or Firefox.
